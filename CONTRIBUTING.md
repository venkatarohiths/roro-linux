# Contributing to Roro Linux

Thanks for contributing.

## Development flow
1. Fork + create branch: `feat/<name>` or `fix/<name>`
2. Keep changes scoped and documented
3. Run relevant checks before PR
4. Open PR using the template

## Commit style
Use conventional prefixes:
- `feat:` new feature
- `fix:` bug fix
- `docs:` documentation
- `chore:` maintenance
- `refactor:` structural change

## PR checklist
- [ ] Change is focused and minimal
- [ ] Docs updated (if behavior changed)
- [ ] Scripts validated where possible
- [ ] No secrets or credentials committed
